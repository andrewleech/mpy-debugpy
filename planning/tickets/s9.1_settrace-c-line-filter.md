# firmware: evaluate a C-level line filter in front of the settrace callback

Phase: EPIC-9 (future, for consideration) / STORY-9.1
Depends on: nothing blocking. A decision on Q16 comes first; the spike below is how
Q16 gets decided. It should follow the upstream review of #8767, because the
filter extends the API that PR adds.
Status: PROPOSED 2026-09-23. Not scheduled.
Anchored at: top repo `1eaf939`, `micropython` `ea87c3501f`, `micropython-lib` `f584db6`

## Context

`planning/20260923_ghi_debugger_comparison.md` compares this project with GHI
Electronics' MicroPython debugger. GHI's engine (`shared/mpdebug/mpdebug_break.c`
at `ghi-electronics/micropython-firmware-debugger@62449e5a0c`) checks breakpoints
in C, on the VM's per-instruction hook. The hook is gated by an `mp_debug_armed`
flag and consults a small breakpoint table only when the source line changes. No
Python runs until something matches. They turn on `MICROPY_PY_SYS_SETTRACE` for
its metadata and hook site only and never use the Python callback.

Our debugpy does the opposite. `DebugSession._trace_function`, which is Python,
runs on every `call`, `line` and `return` event. It drains the socket, then runs
`PdbAdapter.should_stop()` (`BACKGROUND.md`, "Central design constraint: no server
thread"). Code under a debugger therefore runs a Python function call on every
line, even when no breakpoint is anywhere near it.

The idea worth taking from GHI is to keep our architecture (DAP ends on the
device, the primitives are generic and upstreamable, any client can attach) and
let C discard the line events that cannot matter before they become Python calls.

## Scope

In scope:
1. **A measurement spike first.** Measure per-line settrace cost against the
   unarmed baseline, on unix and on an RP2040-class board. This decides Q16.
2. If the spike justifies it, an optional C filter consulted by
   `mp_prof_instr_tick` before `mp_prof_callback_invoke`. debugpy drives it
   through a small `sys` or `micropython` API.
3. The debugpy side: keep the filter in sync with `setBreakpoints`, stepping state
   and pause, and fall back cleanly when the capability is missing.

Out of scope: replacing the Python DAP server, a binary wire protocol,
second-CDC transport (D9 stands), and GHI's always-on idle-hook polling. That
last one is a separate question and is noted in the comparison report.

## Files and anchors

- `micropython/py/vm.c:199-200`: `TRACE_TICK`. The hook site already exists and
  is gated on `MP_STATE_THREAD(prof_trace_callback)`. Nothing changes here.
- `micropython/py/profile.c:398` `mp_prof_instr_tick`: computes `current_line_no`
  and, at `:431-432`, sends the `line` event through `mp_prof_callback_invoke`.
  The filter check belongs immediately before that invoke, after the line has
  changed.
- `micropython/py/profile.c:300` `mp_prof_settrace` / `profile.h:55`: the API
  surface that the filter setter sits beside.
- `micropython/py/profile.c:44` `mp_prof_bytecode_lineno`: the line lookup, which
  already runs, so the filter adds no new lookup.
- `micropython-lib/python-ecosys/debugpy/debugpy/server/pdb_adapter.py`:
  breakpoint and step state. This becomes the source of truth that is pushed
  down to C.
- `micropython-lib/python-ecosys/debugpy/debugpy/server/debug_session.py`
  `_trace_function`: it also pumps the socket. See the design constraints.

## Design constraints

- **The socket pump rides on trace events.** If the filter suppresses most line
  events, the DAP channel is serviced less often. Pause, a late
  `setBreakpoints` and `disconnect` then stall inside tight loops. The filter
  needs a pump escape: pass through every Nth suppressed event, or pass through
  on a time budget. GHI does the same with its 256-branch poll counter
  (`mp_debug_vm_hook`).
- **Stepping** needs every line event in the relevant frames. While a step is
  active the filter must be a pass-through, or it must express frame depth. The
  simplest correct option: a filter is armed only while debugpy is running
  freely with no step pending.
- **`call` and `return` events** are needed for per-frame `f_trace` and step-out.
  Filter only `line` events at first.
- **Capability-gated.** Firmware without the filter must keep today's behaviour
  exactly. The `MPDBG-READY` `caps` gains a `line_filter` key, probed at runtime,
  never inferred from a build name (consistent with D-series capability truth).
- **Upstream shape.** This is a settrace extension to MicroPython core. It has to
  be justifiable to upstream on its own terms, as generic ("don't call me for
  lines outside this set") rather than debugpy-specific, and it must cost nothing
  when unset. Keep it behind a compile-time flag and keep the unset path to one
  pointer test.
- **Breakpoint file identity**: filename qstrs as the VM sees them
  (`MP_CODE_QSTR_MAP(context, 0)`), including `/remote/...` under mount. GHI uses
  suffix matching on path boundaries (`mp_debug_file_matches`), and that pitfall
  applies here too (`util.py` must not match `mathutil.py`).
- **Threads**: `prof_trace_callback` is per thread (`MP_STATE_THREAD`). Decide
  whether the filter is per thread or global. Global is simpler and matches
  debugpy's model.

## Approach sketch

1. **Spike (sonnet + haiku):** a throwaway benchmark with a pystone-like loop in
   `src/pystone.py`. Run it (a) with no trace, (b) with a no-op Python trace fn,
   (c) with debugpy attached and no breakpoints, (d) with debugpy attached and one
   breakpoint in an unrelated file. Run it on the unix port and on the bench
   RP2040/Pico W. Record the numbers in `planning/YYYYMMDD_settrace_cost.md`. The
   case for the change is (c)/(d) against (a). If (c) is within a factor the user
   accepts, close Q16 as "not needed".
2. If going ahead, the minimal C form: a set of (file qstr, line) pairs, or per
   file a bitmap of lines, attached to the thread state and set through
   `sys._settrace_lines(dict | None)` (the name is open). `None` means pass
   everything. In `mp_prof_instr_tick`, after computing a new line: if a filter
   is set and (file, line) is not in it and the pump counter has not expired,
   return without invoking.
3. debugpy: rebuild the filter on `setBreakpoints`. Clear it (pass everything)
   while stepping or while a pause is pending, and re-arm it on `continue`.
4. Prototype on the integration branch as a new local-only mbm branch (for
   example `settrace_line_filter`), registered by hand in `mbm.toml`, the same
   way as `settrace_loop_line_events`.

## Acceptance criteria and tests

- [ ] The spike report exists with numbers for all four cases on both targets,
      and Q16 is closed with a dated DECIDED entry either way.
- [ ] If implemented: with debugpy attached, one breakpoint, and the program
      running freely, the per-line overhead on the benchmark drops by an amount
      stated in the report and measured on hardware.
- [ ] Existing `make test` harness passes, plus the HIL suite, with and without
      the capability (use a firmware built without the flag to prove the
      fallback).
- [ ] Adversarial: pause while a tight loop runs, with the filter armed and no
      breakpoints in that loop, still stops within a bounded time (pump escape
      works).
- [ ] Adversarial: step-in, step-over and step-out across files behave the same
      with the filter available.
- [ ] Adversarial: a breakpoint in `util.py` does not fire in `mathutil.py`.
- [ ] MicroPython core test for the filter API: `tests/misc/sys_settrace_*.py`
      style, with a `.exp` file.

## Workflow shape

The spike is a single agent (sonnet) writing the benchmark, with a human or the
bench running the hardware. Any implementation waits for the Q16 decision. After
that: firmware C (sonnet), debugpy side (sonnet), and tests (haiku) in parallel,
with the filter API signature fixed up front as the contract.

## Open questions

- Is the per-line Python cost actually the bottleneck users feel, compared with
  the transport round-trips while stopped? The spike answers this.
- Does upstream accept a settrace extension like this, or should it live behind a
  separate `micropython`-module hook? Raise it on #8767 before building.
- Per-file line bitmap or a flat (qstr, line) set: memory against lookup cost on
  RP2040.
